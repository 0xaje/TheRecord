# A17 workspace request bounds — owner acceptance OPEN

Workspace requests now have a15-second overall wait bound including response-body parsing and a2MiB response cap. No automatic retry. Network/timeout/5xx/unreadable acknowledgement after a mutation is an uncertain outcome, not proof of failure. Further mutations in that page session are blocked while read-only checks remain available. A page reload resets that session lock; users must inspect state before writing again. This is not server-side idempotency or cancellation of an already committed write.

Check saved state performs reads without replacing editor text. For a known draft it reports current revision and whether exact text matches. For a new draft it checks the visible list page and warns that matching text is not proof of which request created it; missing match is not proof of no write. Pagination is disclosed. Missing/deleted/trashed items retain the server error and can be checked in Trash after reload. Lost invitation credentials cannot be recovered from this read-back; owner can inspect/revoke invitations after reload. Recovery reads complete before identity is replaced.

Known successful save retains its returned draft ID/revision before follow-up refresh, preventing a refresh failure from making the next save create a duplicate. Form controls are disabled during submission and restored to their prior disabled state afterward. The display distinguishes save acknowledgement from subsequent refresh failure.
